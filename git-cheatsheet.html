三条保命规则：① 动手前先 git status 看清状态；② git reset --hard 会丢弃未提交改动，慎用；③ 已经 push 的提交想撤销，用 git revert 而不是 reset。

1初始配置（只做一次）

git config --global user.name "zhangkj123456"
git config --global user.email "19297390@qq.com"
git config --global --list          # 查看全局配置
git config --local user.name "xxx"   # 只对当前仓库生效

2起步：建仓库 / 克隆

git init                  # 当前目录初始化为新仓库
git clone <url>            # 克隆远程仓库
git clone <url> mydir      # 克隆到指定目录
git clone <url> .          # 克隆到当前目录

3日常三板斧（90% 的时间在用）

git status                 # 看改了什么、是否已暂存
git add file.txt           # 暂存指定文件
git add .                  # 暂存当前目录所有改动
git add -u                 # 只暂存已跟踪文件的修改/删除
git commit -m "信息"       # 提交（写清楚改了什么）
git commit -am "信息"      # 跳过 add（仅限已跟踪文件）
git pull                  # 拉取并合并远程最新代码
git push                  # 推送到远程

4分支操作

git branch                 # 列出本地分支
git branch -a              # 列出所有分支（含远程）
git switch dev            # 切换分支（推荐用法）
git switch -c dev         # 新建并切换到 dev
git checkout -b dev       # 老写法，同上
git merge dev             # 把 dev 合并进当前分支
git rebase dev            # 变基，保持提交历史线性
git branch -d dev         # 删除已合并的分支
git branch -D dev         # 强制删除（未合并也能删）

5远程仓库

git remote -v              # 查看远程仓库地址
git remote add origin <url> # 添加远程（名字一般叫 origin
git remote set-url origin <url> # 修改远程地址
git fetch origin          # 只拉取更新，不合并
git pull origin main      # 拉取并合并指定分支
git push -u origin main   # 首次推送，建立追踪关系
git push --delete origin dev # 删除远程分支

6查看历史与差异

git log                    # 完整提交历史
git log --oneline --graph --all # 简洁图形化历史
git log -5                 # 最近 5 条提交
git diff                   # 工作区 vs 暂存区
git diff --staged          # 暂存区 vs 上次提交
git show d1989b3           # 查看某次提交的详情
git blame file.txt        # 逐行看是谁在何时改的

7撤销与回退（救急）

git restore file.txt       # 丢弃工作区改动（还没 add）
git restore --staged file.txt # 取消暂存，保留改动
git reset --soft HEAD~1    # 撤销上次 commit，改动留在暂存区
git reset --hard HEAD~1    # 危险！彻底丢弃改动
git revert d1989b3         # 新提交撤销旧提交，适合已 push
git reflog                 # 找回"丢失"的提交 / 查看所有操作
git commit --amend -m "新信息" # 改最近一次提交信息

8暂存现场（临时切任务）

git stash                  # 把当前改动存起来
git stash push -m "说明"    # 带说明地暂存
git stash list             # 查看暂存列表
git stash pop              # 恢复最近一次暂存并删除记录
git stash apply            # 恢复但保留记录

9标签（版本发布）

git tag                     # 列出标签
git tag v1.0.0              # 创建轻量标签
git tag -a v1.0.0 -m "正式版" # 创建附注标签
git push origin v1.0.0      # 推送单个标签
git push --tags             # 推送所有标签

10git status 常见状态符号

符号含义怎么处理
??未跟踪的新文件git add 或写进 .gitignore
M 已修改并暂存可直接 git commit
M已修改但未暂存先 git add
A 新增且已暂存可直接提交
D 已删除（已暂存）提交即同步删除
UU合并冲突改文件 → git add → git commit

11.gitignore 写法（忽略不该提交的文件）

匹配语法

写法含义
# 注释注释行，不生效
*.log忽略所有 .log 结尾的文件
build/忽略所有名为 build 的目录（含子目录）
/dist只忽略仓库根目录下的 dist
temp/*忽略 temp 目录下的所有文件
!temp/keep.txt例外：不忽略这个文件
**/foo.txt任意层级下的 foo.txt
config.json任意层级下同名的文件都会被忽略

常用模板（按需复制）

# Node.js
node_modules/

build/
*.log
.env
.env.local

# Python
__pycache__/
*.py[cod]
.venv/
venv/
*.egg-info/
.pytest_cache/

# 通用 / 编辑器
.DS_Store
Thumbs.db
*.swp
.idea/
.vscode/
*.bak

四条关键规则： ① 一行一条规则，文件放在仓库根目录，对整个仓库生效； ② / 结尾表示目录，开头表示从仓库根目录算起； ③ * 匹配任意字符（不含 /），** 匹配任意层级； ④ ! 表示例外，但父目录被忽略时子文件的 ! 不生效（要先写 !父目录/）。 

git status --ignored          # 查看哪些文件被忽略了
git check-ignore -v file.log  # 查某文件被哪条规则忽略
git rm --cached file.log      # 已跟踪的文件改忽略：移出暂存区，本地文件保留

⚠️ 注意：.gitignore 只对还没被 Git 跟踪的文件生效。如果文件之前已经 git add 过，光写进 .gitignore 没用，必须执行上面的 git rm --cached 再提交一次。

12常见场景：照着顺序敲就行

A
把本地项目第一次推到 GitHub 
git init
git add .
git commit -m "first commit"
git remote add origin https://github.com/zhangkj123456/YG.git
git branch -M main
git push -u origin main
B
每天开工 / 收工 
git pull                      # 开工：先拉最新代码
… 修改文件 …
git status
git add .
git commit -m "说明改了什么"
git push                      # 收工：推上去
C
改错了，还没 commit 
git restore file.txt          # 回到上次提交的状态
D
commit 信息写错了，还没 push 
git commit --amend -m "正确的信息"
E
已经 push 了，想撤销那次提交 
git revert d1989b3            # 生成一次反向提交，历史安全
git push
F
合并时遇到冲突（UU） 
git status                    # 找到冲突文件
# 打开冲突文件，删掉 <<<<< ===== >>>>>> 标记，保留想要的内容
git add .
git commit -m "解决合并冲突"
git push
